# Testing for `terraform.tfvars` Variable Changes

## Scope

Applies when a PR adds, modifies, or removes a top-level `terraform.tfvars` variable that drives any generated artefact under [`assets/src/`](../../assets/src/) — `tower.yml`, `tower.env`, `docker-compose.yml`, `tower.sql`, Ansible files, Wave-Lite config, etc.

The tests only catch drift on assertions that exist. A value hard-coded in a template is a silent gap until it becomes a variable; this guideline fills that gap at PR time.

## How the framework works

- **Rendering.** At session start, `tests/utils/terraform/precompute.py` renders every template once per distinct tfvars scenario with `terraform console` (no plan, no apply) and caches the output in `tests/.scenario_cache/<key>/`. The key hashes the tfvars text plus every file that affects rendering (`tests/utils/cache/cache.py:_compute_static_hash_part`).
- **Scenarios.** A test declares its tfvars with `@pytest.mark.tfvars(BASELINE + <FEATURE> + ...)`. The strings are tfvars fragments; later fragments win when a variable repeats.
- **Assertions.** Each test merges delta dicts (`merge_deltas`) and checks them with `assert_all_deltas`. The check is strict per template: every rendered file needs an entry, and each entry lists keys that must be `present` (with values) and keys that must be `omitted`.
- **Baseline.** `BASELINE` renders the `TEMPLATE_terraform.tfvars` defaults plus `tests/datafiles/base-overrides.auto.tfvars` (generated by `tests/datafiles/generate_core_data.sh`), pinned to the test Platform version. `BASELINE_ASSERTIONS` describes that output.

All deltas live in [`tests/unit/config_files/expected_deltas.py`](../../tests/unit/config_files/expected_deltas.py); the tests live in [`tests/unit/config_files/test_config_file_content.py`](../../tests/unit/config_files/test_config_file_content.py).

## Required steps

1. **Update `BASELINE_ASSERTIONS` for the template default.** Add the rendered key and value to `present`, or the key to `omitted` when the default renders nothing. When the default renders a comment line such as `# TOWER_X_NOT_SET=DO_NOT_UNCOMMENT`, assert that line in `present` and the real key in `omitted`.
2. **Add the feature pair.** Add a `<FEATURE>_ACTIVE` tfvars string and a `<FEATURE>_ACTIVE_ASSERTIONS` delta that lists only what changes from the baseline. Add one test that merges `BASELINE_ASSERTIONS` with it. For an object variable, the tfvars string sets every key, because required object keys have no defaults.
3. **Cover sub-options with a stacked delta.** A restriction or variant of a feature gets its own pair that stacks on the feature (for example, `DATA_LINEAGE_WORKSPACE_RESTRICTION_ACTIVE` after `DATA_LINEAGE_ACTIVE`).
4. **Cover interactions with an `_X_` delta, only when needed.** When two features change each other's output, add `<A>_X_<B>_DELTA` with just the interaction (for example, `DB_EXTERNAL_NEW_X_WAVE_LITE_DELTA`).
5. **Cover both sides of a version gate.** If the output depends on `tower_container_version`, stack a version override such as `FRONTEND_PRE_26_2_ACTIVE` and assert both sides (for example, `test_data_lineage_pre_26_2_active`).
6. **Use the key syntax for the file type:**

   | File type | Key syntax | Example |
   | --------- | ---------- | ------- |
   | `*.env` | Plain key, including comment lines | `TOWER_DB_URL`, `# TOWER_OIDC_PEM_PATH_NOT_SET` |
   | `*.yml` | YAMLPath (dot-separated) | `tower.participant.auto-create-user` |
   | `*.yml` list items | YAMLPath search | `services.cron.volumes[.%usage-metrics]` |
   | `*.sql`, Ansible, plain text | Substring set | `{"Creating data directory on host for Studios."}` |

7. **Stub any new resource attribute.** `terraform console` can't resolve a resource attribute before apply (for example, `random_password.<name>.result`), and one unknown value makes the whole rendered file unknown. Reference the attribute directly in the `templatefile()` arguments in `009_define_file_templates.tf`, then add a stub pattern and value to `_replace_refs` in `precompute.py`, next to the existing `tls_private_key.connect_ssh_host_key` stub.
8. **Test each new `validation {}` block.** Add a bad value and a short reason to `SCENARIOS` in [`tests/unit/variable_validation/test_variable_validation.py`](../../tests/unit/variable_validation/test_variable_validation.py). This suite takes 30 seconds or more; run it with `make run_tests_variables_only`.
9. **Run the core suite from a clean cache.** Run `make purge_cache`, then `make run_tests_core_only`. The precompute line must report `0 miss-err`.

## Don't

- **Don't put feature values in `base-overrides.auto.tfvars`.** The baseline tracks the template defaults. Turn a feature on in its own tfvars string instead.
- **Don't change `templates/TEMPLATE_terraform.tfvars` defaults to simplify tests.** That is a deployment-policy change that needs a CHANGELOG entry and stakeholder review, per [`changelog_protocol.md`](changelog_protocol.md).
- **Don't add a new test file or a new kind of test without user sign-off.** Feature pairs in `expected_deltas.py` are the normal case and need no sign-off. Propose anything else first, with the reason the existing pattern can't cover it.
- **Don't trust a failure in `test_console_locals_resolvability` after a branch switch.** Leftover cache folders from other branches cause false "key absent" or "locals.json missing" failures. Run `make purge_cache` and rerun before you investigate.
